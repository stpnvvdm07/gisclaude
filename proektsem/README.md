# proektsem — средовой анализ дворов, Коньково, территория № 2

## Главное
**`ГИС_Коньково.py`** (в этой папке) собирает чистые ГИС для ручного анализа:
- `ГИС/Коньково_ГИС.gpkg` — все слои в одном файле, русские названия слоёв и полей, стиль каждого слоя сохранён внутри
  (перетащите слой в любой проект QGIS — он откроется уже раскрашенным);
- `ГИС/Коньково_ГИС.qgz` — готовый проект: группы «Основа», «Дворы и входы», «Пути», «Контроль и освоенность», «Проблемы», «Предпосылки»,
  вид повёрнут как на картах команды (улицы по осям).

Запуск в QGIS: Модули → Консоль Python → «Показать редактор» → открыть `ГИС_Коньково.py` → ▶. Слои добавятся в открытый проект группой «Коньково — ГИС».

## Что где лежит
| Папка / файл | Что внутри |
| --- | --- |
| `ГИС_Коньково.py`, `ГИС/` | чистые ГИС для ручного анализа (см. выше) |
| `proektsem.qgz` | рабочий проект QGIS команды, ссылки переведены на `*_v16.gpkg` |
| `vector/исходные_данные.gpkg` | исходные слои анализа в одном файле: обследование, здания, сеть путей, ячейки с ручным расчётом комфорта (xlsx команды), зоны загрузки (competitions_2), транспортное дерево (roads_counts) |
| `vector/konkovo_v16.gpkg`, `analiz_v16.gpkg`, `problems_v16.gpkg` | результаты расчёта (из них собирается `ГИС/`) |
| `vector/basemap`, `proektbase`, `people_dens.gpkg`, `3d/` | подоснова OSM, исходники команды, 3D-модель ячеек |
| `analysis/` | расчёт: `s1_base.py` → `s2_network.py` → `s3_control_osv_flags.py` (нужны geopandas и scipy) |
| `qgis_plugin/konkovo_tools/` | плагин QGIS «Коньково»: обновить слои до последней версии, удалить ненужные слои |
| `tools/clean_project.py` | перевод `proektsem.qgz` на последние версии gpkg без запуска QGIS |
| `presentation/` | презентация (`deck.pptx`, `deck.pdf`) — по анализу v15, не обновлялась |
| `design/`, `raster/` | шрифты и стиль команды, топооснова DWG |

## Как пересчитать
```
python3 analysis/s1_base.py && python3 analysis/s2_network.py && python3 analysis/s3_control_osv_flags.py
python3 ГИС_Коньково.py          # или запуск из консоли QGIS
```

- **Транспортное дерево** — слой команды roads_counts как есть (103 участка, нагрузка 1–9), вместо автоматического.
